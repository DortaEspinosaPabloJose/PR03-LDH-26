Detailed Description

Fase constructiva de la metaheurística GRASP para el TOPTW.

Implementa un procedimiento GRASP (Greedy Randomized Adaptive Search Procedure) para el problema de orientación por equipos con ventanas de tiempo (Team Orienteering Problem with Time Windows, TOPTW), núcleo del recomendador turístico RTVRPTW. Cada ruta representa el itinerario de un día/vehículo, cada cliente un punto de interés (POI) y el objetivo es maximizar la puntuación total de los POIs visitados respetando sus ventanas de tiempo y la duración máxima de cada ruta.

Esquema del algoritmo

  1. Se construye una solución voraz aleatorizada (computeGreedySolution()):
    • se evalúa la mejor posición de inserción de cada cliente libre (comprehensiveEvaluation());
    • se ordenan los candidatos por coste incremental y se forma la lista restringida de candidatos (RCL) con los maxSizeRCL mejores;
    • se elige un elemento de la RCL (aleatoria o difusa) y se inserta en la ruta (updateSolution());
    • si no quedan candidatos factibles se abre una nueva ruta, mientras haya vehículos.
  2. Se evalúa la solución y se actualizan las estadísticas (media y mejor valor).
  3. (Pendiente) Búsqueda local sobre la solución construida.

Formato de un candidato

Los candidatos se representan como double[5]:

Índice Contenido
0 Identificador del cliente (POI) a insertar
1 Índice de la ruta en la que se inserta
2 Nodo predecesor tras el cual se inserta el cliente
3 Coste: instante en que termina la ruta tras la inserción
4 Puntuación (score) del cliente

◆ comprehensiveEvaluation()

ArrayList< double[] > top.TOPTWGRASP.comprehensiveEvaluation ( ArrayList< Integer > customers,
ArrayList< ArrayList< Double > > departureTimes )

Evalúa, para cada cliente libre, su mejor posición de inserción factible.

Para cada cliente se prueban todas las posiciones de todas las rutas creadas (tras cada nodo pre, incluido el depósito). Una inserción es factible si:

  • se llega al cliente antes del cierre de su ventana de tiempo (se espera si se llega antes de la apertura);
  • la salida del cliente permite llegar a tiempo a su sucesor y a todos los nodos posteriores de la ruta (propagación del retraso);
  • ningún instante supera la duración máxima de la ruta (TOPTW.getMaxTimePerRoute()).

De entre las posiciones factibles se conserva la de menor coste, entendido como el instante en que finaliza la ruta tras la inserción. Los clientes sin ninguna inserción factible no aparecen en el resultado.

Parameters
customersclientes (POIs) aún no asignados a ninguna ruta.
departureTimestiempos de salida por ruta y nodo (ver computeGreedySolution()).
Returns
lista de candidatos, uno por cliente, con formato [cliente, ruta, predecesor, coste de tiempo, score].

◆ computeGreedySolution()

void top.TOPTWGRASP.computeGreedySolution ( int maxSizeRCL)

Construye una solución voraz aleatorizada completa.

Reinicia la solución (TOPTWSolution.initSolution()) y, mientras queden clientes sin asignar y sea posible, repite:

  1. Reevaluar la mejor inserción de cada cliente libre (comprehensiveEvaluation()) y ordenar los candidatos por coste ascendente.
  2. Construir la RCL con los maxSizeRCL mejores candidatos.
  3. Elegir uno de la RCL y insertarlo (updateSolution()).
  4. Si no hay ningún candidato factible, abrir una nueva ruta (TOPTWSolution.addRoute()); si ya se usaron todos los vehículos, terminar.

El método de selección está fijado internamente (selection = 3, corte alfa con alpha = 0.8); las opciones son: 1 = aleatoria, 2 = difusa determinista, 3 = difusa con corte alfa.

Se mantiene una lista de tiempos de salida por ruta: departureTimesPerClient.get(k).get(n) es el instante en que se abandona el nodo n en la ruta k (0 para el depósito).

Parameters
maxSizeRCLtamaño máximo de la RCL; se limita al número de candidatos disponibles.

Selección difusa con corte alfa y elección aleatoria.

Se calcula el grado de pertenencia 1 - score / maxScore de cada candidato y se conservan los que cumplen pertenencia <= alpha (corte alfa). Entre ellos se elige uno al azar. Si ninguno supera el corte, se elige al azar entre todos los elementos de la RCL.

◆ fuzzySelectionBestFDRCL()

int top.TOPTWGRASP.fuzzySelectionBestFDRCL ( ArrayList< double[] > rcl)

Selección difusa determinista: elige el candidato con mejor grado de pertenencia.

El grado de pertenencia de un candidato es 1 - score / maxScore, donde maxScore es la mayor puntuación de todos los POIs (getMaxScore()). Cuanto menor es el valor, mejor es el candidato; por tanto se elige el de mayor puntuación. En caso de empate gana el primero.

void top.TOPTWGRASP.GRASP ( int maxIterations,
int maxSizeRCL )

Ejecuta el procedimiento GRASP durante un número fijo de iteraciones.

En cada iteración construye una solución con computeGreedySolution(), la evalúa con TOPTWSolution.evaluateFitness() y acumula la media y el mejor valor de la función objetivo (suma de scores). El bloque de búsqueda local está aún por implementar.

Efectos por consola: imprime el informe detallado de cada solución (TOPTWSolution.getInfoSolution()), y al final la media y el mejor valor obtenidos. No se conserva la mejor solución, sólo su valor.

Parameters
maxIterationsnúmero de construcciones (iteraciones) a realizar; debe ser mayor que 0.
maxSizeRCLtamaño máximo de la lista restringida de candidatos (RCL). Valores pequeños son más voraces; valores grandes, más aleatorios.
